## What stayed the same

Both source revisions read the same cached bytes from the census's two
revision-pinned manifests. The replay compares complete JSON reports, including
reader integrity notes and repeated-step evidence, rather than only counting
findings. This is a compatibility check, not a new measurement of diagnostic
accuracy against ground truth.

| Result | Logs |
| --- | ---: |
| Readable, exactly equal reports | 3,939 |
| Readable, only floating-point roundoff differs | 238 |
| Remain unreadable | 82 |
| Substantive differences | 0 |
| Total compared | 4,259 |

All **4,177 readable logs** keep the same finding titles, severities, messages,
counts, and step boundaries. Numeric evidence uses a relative tolerance of
`1e-10` or an absolute tolerance of `1e-12`; all other fields must match exactly.
The [corpus ledger](verification-long-histories-corpus.json) records manifest,
source-module and output hashes. Its elapsed times include replay bookkeeping
and overlapping verification work; they are not the isolated CLI benchmark.

Independent numerical checks also compare the new fits against 80-digit
Decimal arithmetic and the median windows against sorted-window definitions.
The direct fit intentionally corrects the old intercept-cancellation error at
very large offsets. See [the algorithm and its limits](long-histories.md).
